# ShulkerSorter v1.1 — Improvements Design

Date: 2026-05-14
Status: Approved

## Overview

Full review of the mod resulting in 4 bug fixes/cleanups and 3 new features, targeting a v1.1 release.

---

## Section 1 — Bug Fixes & Small Improvements

### 1.1 Remove dead `config.keybind` field

**Problem:** `ShulkerSorterConfig` stores and loads a `keybind` string, but it is never applied anywhere. `SortKeybindHandler` hardcodes `GLFW_KEY_J`. The correct approach in Fabric is to register a `KeyMapping` with a default key and let Minecraft's *Options → Controls* screen handle user customization — which is already happening.

**Fix:**
- Remove `keybind` field from `ShulkerSorterConfig` (field, load, save)
- Remove `keybind` from TOML read/write in `ShulkerSorterConfig.load()` / `save()`
- No change needed in `SortKeybindHandler` — keybind stays as-is

### 1.2 Fix tooltip "more items" counter

**Problem:** `ShulkerTooltipRenderer` computes `remaining` (total item count of hidden stacks) but passes `hiddenTypes` (number of hidden item types) to the translation key `shulkersorter.tooltip.more`, which says "... and %1$s more items". The item count is calculated but thrown away.

**Fix:** Replace `hiddenTypes` with `remaining` in the `translatable(...)` call.

```java
// Before
int hiddenTypes = itemNames.size() - maxLines;
lines.add(... translatable("shulkersorter.tooltip.more", hiddenTypes) ...);

// After
lines.add(... translatable("shulkersorter.tooltip.more", remaining) ...);
```

### 1.3 Show item count in success message

**Problem:** `SortResult` already tracks `itemsMoved` and passes it to `success()`, but `NotificationHelper.sendSuccess` ignores it. The success message only shows box count.

**Fix:**
- Update `NotificationHelper.sendSuccess(player, boxCount)` → `sendSuccess(player, boxCount, itemCount)`
- Update **both** call sites in `SortKeybindHandler`: `sortOnServer` (server thread) and `sortClientAndSyncCreative` (client thread) — both already have access to `result.itemsMoved()`
- Update translation keys:
  - `shulkersorter.message.success` → `"ShulkerSorter: %1$s boxes sorted, %2$s items distributed."`
  - `de_de`: `"ShulkerSorter: %1$s Boxen sortiert, %2$s Items verteilt."`

### 1.4 Fix CHANGELOG.md

Replace "Cloth Config screen" with "YACL config screen".

## Section 2 — Skip Empty Boxes Option

**New config field:** `skipEmptyBoxes: boolean` (default: `false`)

**Behavior:** When enabled, shulker boxes for which `ShulkerBoxHelper.isEmpty()` returns `true` are excluded from `sortableBoxes` during Phase 1 (SCAN). They are treated as if they don't exist — not assigned, not written to, left untouched in the inventory.

If remaining boxes don't have enough capacity for all items, the existing `"not_enough_space"` error is shown.

**Config screen:** New checkbox in the "Sorting" tab, placed after "Include Loose Items".

**New translation keys:**
- `config.shulkersorter.skip_empty_boxes` → "Skip Empty Boxes" / "Leere Boxen überspringen"
- `config.shulkersorter.skip_empty_boxes.tooltip` → "When enabled, empty shulker boxes are ignored during sorting and left untouched." / "Wenn aktiviert, werden leere Shulker Boxes beim Sortieren ignoriert und nicht verändert."

**TOML key:** `skip_empty_boxes`

## Section 3 — Undo Function

**Trigger:** Shift + Sort keybind. In `SortKeybindHandler.onClientTick`, check for `sortKeybind.consumeClick()` AND `Screen.hasShiftDown()` BEFORE checking for regular sort.

**New class:** `SortUndoManager` (client-only singleton, lives in `src/client/`)

```
SortUndoManager
  - snapshot: List<ItemStack> (36 entries, indices 0–35, copies)
  - hasSnapshot(): boolean
  - saveSnapshot(Inventory): void   — deep-copies all 36 slots
  - restore(Inventory): void        — writes slots back, clears snapshot
  - clear(): void
```

**Snapshot lifecycle:**
1. In `SortKeybindHandler.onClientTick`, the snapshot is saved from `client.player.getInventory()` on the **client thread**, immediately before dispatching the sort (before `sortOnServer` or `sortClientAndSyncCreative`). This is safe because the client inventory is always in sync at the time of keypress.
2. On successful sort: snapshot is kept. On failed sort: snapshot is discarded (`clear()`).
3. On Shift + Sort: if `hasSnapshot()` → restore → send "undo success" → clear. If no snapshot → send "nothing to undo".
4. Snapshot is NOT invalidated by inventory changes after the sort — the user is responsible.

**Restore execution path:**
- **Singleplayer:** `SortUndoManager` hands the snapshot to the server thread (via `integratedServer.execute(...)`) where it is written into `serverPlayer.getInventory()` and `broadcastChanges()` is called, mirroring how `sortOnServer` works.
- **Multiplayer creative:** Snapshot is written directly into `client.player.getInventory()` and synced via creative packets, mirroring `sortClientAndSyncCreative`.

**Multiplayer constraint:** Undo only works in the same execution paths as sort (singleplayer + multiplayer creative). In multiplayer survival the undo button shows the "nothing to undo" message since a sort could never have succeeded.

**New translation keys:**
- `shulkersorter.message.undo_success` → "Sort undone." / "Sortierung rückgängig gemacht."
- `shulkersorter.message.undo_nothing` → "Nothing to undo." / "Nichts rückgängig zu machen."

## Section 4 — Category Editing UI

### 4.1 New config fields

Add to `ShulkerSorterConfig`:
```java
public Set<String> disabledCategories = new LinkedHashSet<>();
```

TOML key: `disabled_categories` (string list)

In `ItemCategorizer.categorize()`, skip categories that are in `config.disabledCategories` in both Pass 1 and Pass 2. Disabled category items fall through to `misc`.

### 4.2 New "Categories" tab in YACL Config Screen

The tab is built dynamically from `config.categoryOrder` each time the screen opens.

**Group 1 — "Category Order"**
A `ListOption<String>` bound to `config.categoryOrder`. The user can reorder entries using YACL's built-in up/down arrow buttons, remove entries, or add new category keys. Saving updates `config.categoryOrder`.

**Groups 2–N — One group per category**
Built by iterating `config.categoryOrder`. Each group:

1. **Enable/Disable checkbox** — bound to `config.disabledCategories` (checked = enabled, i.e. NOT in the set)
2. **Patterns `ListOption<String>`** — bound to the category's pattern list in `config.categories`

Groups are collapsible (YACL's default `OptionGroup` behavior).

### 4.3 Translation keys

- `config.shulkersorter.category.categories` → "Categories" / "Kategorien"
- `config.shulkersorter.category_order` → "Category Order" / "Kategorienreihenfolge"
- `config.shulkersorter.category_order.tooltip` → "Order in which categories are assigned during sorting. Items are matched against categories from top to bottom." / "Reihenfolge der Kategorien beim Sortieren."
- `config.shulkersorter.category.enabled` → "Enabled" / "Aktiviert"
- `config.shulkersorter.category.enabled.tooltip` → "Disabled categories are skipped; their items go to Misc." / "Deaktivierte Kategorien werden übersprungen; ihre Items landen in Sonstiges."
- `config.shulkersorter.category.patterns` → "Patterns" / "Muster"
- `config.shulkersorter.category.patterns.tooltip` → "Item ID patterns for this category. Prefix: 'raw_', Suffix: '_planks', Exact or contains: 'redstone'." / "Item-ID-Muster für diese Kategorie."
